## Description

The existing benchmark lane builds xpact with Windows EiffelStudio/MSVC, while its direct C libexpat comparison runs through WSL. Add a separate lane that builds xpact with Linux EiffelStudio/GCC and measures both executables inside Linux, excluding Windows-to-WSL startup overhead.

The runner isolates each Eiffel build mode, verifies the generated GCC compiler, records versions and flags, and invalidates measured reports before rebuilding. Failed builds, benchmark failures and report-write failures cannot leave a previous successful measurement presented as the new result.

- Add a PowerShell WSL2 wrapper and portable Python runner for finalized, finalized-with-assertions and optional workbench builds, including normal and suspended GC.
- Make the benchmark ECF portable and conditionalize the Windows Base precompile.
- Add an opt-in Jenkins stage to both pipelines and run the new orchestration tests in GitHub Actions.
- Document the same-computer xpact comparison and commit its 24 raw repetitions. Finalized throughput was 13.629 MiB/s on MSVC versus 12.400 on WSL/GCC with assertions off, and 1.434 versus 1.535 with assertions on. These results include OS/runtime differences and do not isolate the C compiler.

### Validation

- 14 new lifecycle/timing tests pass on Windows Python 3.14 and WSL Python 3.8.
- All 28 existing W3C harness tests pass on Windows.
- Actual WSL2 builds and timings completed for all three Eiffel modes: 10,000 documents, one warmup and three measured repetitions per variant.
- Fresh MSVC finalized builds and timings completed with assertions off/on and normal/suspended GC.
- PowerShell syntax, Python compilation, raw comparison workload consistency and staged whitespace checks pass.

The committed WSL runner uses the distribution's libexpat for its C baseline; the published compiler-comparison snapshot concerns xpact itself. Live Jenkins execution remains unverified; the new lane defaults to disabled and requires Linux EiffelStudio configured for the Jenkins account.
