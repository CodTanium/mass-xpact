## Description

Jenkins build 67 compiled the native suite, then CTest reported `***Exception: SegFault`. The adapter labelled any nonzero result as expected whenever the expected-failure list was nonempty, while leaving CTest's exit code 8 active for the Jenkins wrapper. This produced a reassuring message followed by a failed stage.

Require a complete upstream test summary, reconcile its failure count, and match every observed failure against the expected source/name patterns. Resolve declaration sources from the manifest because assertions can originate in shared helpers. Reject crashes, incomplete output, ambiguous tests, setup/teardown failures, and unlisted failures. Print verbose CTest output, replace the previous run's log before build preparation, fail on log persistence errors, and restore the process environment. Clear LASTEXITCODE only after validating an accepted result.

Add six orchestration regression tests and run them in both Jenkins pipelines. Update the adapter and parity documentation to distinguish expected-failure metadata from observed test outcomes.

Validation: all six behavioral tests passed under Windows PowerShell 5.1 and PowerShell 7, including failure/retry sequences, native exit-code propagation, helper-source attribution, stale logs, failed log persistence, and environment restoration. Full-adapter checks with real installed CTest verified child exit 1 -> CTest 8 -> accepted wrapper exit 0, plus complete-pass handling. The saved build-67 crash log is now rejected explicitly. `git diff --check` passed.

The underlying native crash remains unresolved. Diagnostic runs also found failures and a GC crash after excluding allocator tests; callback assertions using longjmp across Eiffel frames strongly implicate invalid GC roots. This PR corrects reporting and acceptance criteria. The full native suite and Jenkins pipeline have not passed.
