## Description

The Windows Phase 1 Jenkins pipeline passes an absolute ADAPTER_OUTPUT path. The adapter unconditionally prepended the repository root, producing a path such as `C:\...\xpact\C:\...\xpact\build\libexpat-adapter-current`. Windows PowerShell then rejected the path in New-Item before generating the manifest.

Preserve rooted output paths and continue resolving relative paths from the repository root, matching the adapter's existing path handling for libraries and mapping files. Document the OutputDir behavior.

Validation: reproduced the original NotSupportedException under Windows PowerShell 5.1. Verified Manifest mode against Expat 2.8.1 under Windows PowerShell 5.1 and PowerShell 7 with absolute paths containing spaces, explicit relative paths from a different working directory, default output paths, repeated runs, and a missing-source failure followed by a successful retry. All three report files matched across output-path variants within each shell; temporary outputs were cleaned up. `git diff --check` passed.

The full Jenkins job and native C suite have not been rerun.
