STEP BACK 2 - WHAT THE W3C TEST DOES
------------------------------------
Jenkins feeds xpact 2,585 official XML test files from W3C (the people who
write the XML standard), twice: once with the normal build and once with the
assertions build. Each file has a known right answer, "accept" or "reject".
Jenkins checks whether xpact gives that answer.


STEP BACK 1 - THE "SKIP METHOD" WE REMEMBER
-------------------------------------------
On 2026-10-23, xpact got 519 answers wrong (236 + 236 wrong verdicts, plus 47
crashes). To quiet Jenkins while working, a known-failures list was made:
benchmarks/w3c-known-failures.tsv. Cases on that list stop turning the build red.

  - First all 519 failures were put on it. That was the skip.
  - Then the parser was really fixed, and the list was emptied before it was
    committed. On main it has 0 rows: the tool is still there, but switched off.

So the known-failures list is NOT what produces the 1,716 skips.
