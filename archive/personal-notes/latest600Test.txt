2. THE 11 TESTS NOT DONE YET
----------------------------

HIGH VALUE - likely to find real bugs

[ ] #1  W3C output comparison                                 Effort: small-medium
    Checks:    does xpact report the right text, attributes and events, not just accept/reject?
    Procedure: many valid W3C tests have an OUTPUT file with the expected result. Parse each one
               through xpact.dll, write the events in the same format, compare with that file.
               Files are already in our xmlconf folder.

[ ] #2  W3C suite fed in pieces                               Effort: medium
    Checks:    same result for whole file, split at every byte, and byte by byte?
    Procedure: run all 2,585 cases each of the three ways; compare answer and events with the
               whole-file run. Uses our runner plus the dual-lane code.

[ ] #3  Fuzzing                                               Effort: medium
    Checks:    do millions of random/changed inputs cause crashes or hangs?
    Procedure: libexpat's fuzzer (expat/fuzz/, OSS-Fuzz) or xml-fuzz against xpact.dll;
               record every crash or timeout.

[ ] #4  Differential test against Expat                       Effort: medium
    Checks:    same answer and events as Expat on the same random input?
    Procedure: generate documents, run each through both parsers, compare. Every difference
               is a bug or a known difference.

[ ] #5  Security and limits                                   Effort: small-medium
    Checks:    billion laughs, quadratic blow-up, very deep nesting, huge names/attributes,
               external entities (XXE).
    Procedure: Expat's security-bug regression tests and billion-laughs settings, plus C-API
               misuse checks.

[ ] #6  Expat's own C tests (runtests)                        Effort: depends on the row
    Checks:    finish the parity work: the red rows plus the allocator tests.
    Procedure: build runtests against xpact.dll (like Jenkins's native stage), compare with
               parity.tsv and expected-failures.tsv.

MEDIUM VALUE - broader coverage

[ ] #7  libxml2's test files                                  Effort: medium
    Checks:    hundreds of extra, tricky real-world XML files.
    Procedure: download libxml2's test/ folder; check accept/reject and compare with Expat.

[ ] #8  Encodings                                             Effort: small
    Checks:    UTF-16 LE/BE with and without BOM, ISO-8859-1, US-ASCII, unknown-encoding
               handler, broken UTF-8.
    Procedure: inputs from Expat's tests, W3C and our own; each parsed whole and split.

[ ] #9  Memory checks                                         Effort: medium
    Checks:    leaks and bad memory access in the C bridge.
    Procedure: create and free parsers thousands of times, watch memory (Dr. Memory or ASan
               if available).

[ ] #10 Python's own XML tests                                Effort: large
    Checks:    can xpact really replace Expat?
    Procedure: build CPython's pyexpat against xpact.dll; run test_pyexpat, test_xml_etree,
               test_sax, test_minidom.

[ ] #11 Large real files                                      Effort: small
    Checks:    speed and stability on big files.
    Procedure: bigger inputs (Wikipedia, OpenStreetMap or XMark style) through
               run_large_xml_benchmarks.ps1.
